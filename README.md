# Avito Raw Export

Отдельный open-source инструмент, не связанный с AI Sales Agent. Локальная read-only утилита с простым UI для максимально полного сохранения сырых данных, доступных через Avito Business API.

## Для чего

Инструмент решает только задачу архивации. Он **не анализирует**, не очищает, не объединяет и не интерпретирует переписки.

Основной принцип: **API отдал поле → поле должно остаться в RAW-архиве**.

## Что делает v0.2

1. Авторизуется через `client_credentials`.
2. Получает `/core/v1/accounts/self`.
3. Обходит объявления со статусами `active`, `removed`, `old`, `blocked`, `rejected`.
4. Для каждого объявления сохраняет доступную карточку.
5. Ищет чаты несколькими независимыми проходами:
   - глобально;
   - отдельно по типам `u2i`, `u2u`, `a2u`;
   - отдельно по каждому найденному `item_id`.
6. Для каждого найденного `chat_id` сохраняет полный объект чата.
7. Для каждого чата выгружает доступные страницы сообщений V3 до ограничения публичного API.
8. Находит `voice_id`, получает временные URL голосовых и сразу скачивает файлы.
9. Сохраняет Avito-hosted изображения/аватары/доступные медиа, обнаруженные в ответах API.
10. Получает `/ratings/v1/info` и сохраняет рейтинг аккаунта как RAW JSON.
11. Выгружает все доступные страницы `/ratings/v1/reviews` (`limit=50`, `offset` до конца списка), не отбрасывая ни одного поля.
12. Находит связанные с отзывами объявления и доступные изображения отзывов.
13. Пишет журнал ошибок, чтобы не скрывать недоступные данные.

## Read-only

Экспортёр содержит только GET-операции к данным аккаунта. POST используется только для OAuth-токена `/token` и не меняет данные аккаунта. Методы отправки сообщений, удаления, отметки прочитанным, blacklist, webhook и изменения объявлений в коде отсутствуют.

## Структура архива

```text
exports/
└── 2026-09-06_120000_account_123456789/
    ├── manifest.json
    ├── raw/
    │   ├── account/
    │   ├── items/
    │   ├── chats/
    │   ├── messages/
    │   ├── ratings/
    │   │   ├── info.json
    │   │   └── reviews/
    │   └── voice/
    ├── index/
    ├── media/
    └── logs/
```

Каждый RAW-файл сопровождается `*.meta.json` с URL запроса, параметрами, HTTP-статусом, заголовками (секретные заголовки редактируются), размером и SHA-256.

## Запуск на Windows

Требуется Python 3.11 или новее. Самый простой вариант из исходников — двойной клик по `run_windows.bat`. Скрипт создаст `.venv`, установит зависимости и откроет UI в браузере.

Или:

```bash
python -m pip install -e .
python -m avito_raw_export
```

UI доступен локально на `http://127.0.0.1:8765`.

## Профили аккаунтов

В UI можно сохранить несколько профилей. Название и Client ID хранятся в локальном конфиге пользователя; Client Secret передаётся в системное хранилище секретов через `keyring` (на Windows — Credential Manager, если backend доступен).

Сами выгрузки, recovery.sqlite3 и локальные профили не должны попадать в публичный репозиторий и исключены через `.gitignore`.

## Сборка Windows

```bat
build_windows.bat
```

Скрипт использует PyInstaller. Автоматическая Windows-сборка также описана в `.github/workflows/build-windows.yml`.

## Ограничения API

У Messenger API на текущем контракте `limit <= 100`, `offset <= 1000` для списка чатов и сообщений. Экспортёр делает все допустимые страницы `0..1000`. Чтобы увеличить полноту списка чатов, он дополнительно повторяет поиск по каждому найденному объявлению и по типам чатов.

Отзывы API возвращает как список активных опубликованных отзывов. Экспортёр сохраняет всё, что возвращает этот endpoint, включая `id`, `score`, `stage`, `text`, `usedInScore`, `canAnswer`, `createdAt`, `sender`, `item`, `images`, `extraParams`, `answer` и любые новые/неизвестные поля, которые появятся в RAW JSON.

Если Avito API не отдаёт некоторую старую сущность, read-only экспортёр не может восстановить её сам. Ошибка/ограничение при этом фиксируется в журнале.

Для корпоративной иерархии аккаунтов нужен ключ основного аккаунта компании: ключ сотрудника может не видеть часть чатов компании.

## Безопасность публичного репозитория

Никогда не коммитьте:

- Client Secret / access token;
- папки `exports/`;
- сырые чаты;
- медиа;
- логи реальных выгрузок.

## Результаты технической проверки и защита

Подробности изменений и проверок: [AUDIT.md](AUDIT.md).
Политика публикации: [SECURITY.md](SECURITY.md). `.env.example` не используется:
вводите ключи в UI. Client ID также считается приватным и не публикуется.

- Все GET-ответы, включая ошибки и повторы, сохраняются в `raw/requests/`;
  тематические RAW-файлы дополнительно удобны для навигации.
- OAuth-токены и тела ответов `/token` не записываются в архив.
- `manifest.json` содержит `running`, `completed`, `partial`, `interrupted` или `failed`.
  `completed` означает завершение выбранных этапов, а не доказательство полноты
  истории на стороне Avito. Лимиты, повторы и неожиданные форматы дают `partial`.
- Пагинация продолжает запросы после коротких страниц до пустой страницы,
  известного total либо предела API. Поэтому счётчик страниц включает пустые.
- Медиа с внешних доменов остаются ссылками в RAW. HTTPS Avito-домены проверяются
  также при перенаправлениях. Неизвестные CDN требуют явного расширения списка.
- Параллельные вкладки имеют отдельные формы; архивы получают уникальные имена.

## Первое реальное подключение

В локальном UI введите название профиля, Client ID и Client Secret вашего
Avito Business API приложения, нажмите «Проверить подключение», затем сохраните
профиль. Ключ должен иметь доступ к нужным разделам API; отсутствие прав отражается
в ошибках частичного экспорта. Для корпоративного аккаунта используйте подходящие
ключи основного аккаунта. Секреты не отправляйте в GitHub, issues или переписку.

Реальная проверка доступа и полноты проводится отдельно по
[CODEX_LIVE_VALIDATION.md](CODEX_LIVE_VALIDATION.md); текущие тесты используют
только синтетические ответы. Экспорт не является согласованным снимком: новые
сообщения во время обхода offset-страниц могут сдвигать выдачу.

## Продолжение выгрузки (v0.2)

1. Запустите `run_windows.bat` и выберите тот же сохранённый профиль аккаунта.
2. В «Папка для выгрузок» укажите прежнюю папку. UI запоминает её локально.
3. В списке «Незавершённая выгрузка» выберите архив. Последний выбран автоматически.
4. Нажмите **«Продолжить последнюю выгрузку»**. Кнопка **«Начать новую»** создаёт
   отдельный архив. **«Остановить с сохранением»** завершает работу у checkpoint.

Поддерживается восстановление v0.1 с `running`, `partial`, `failed` и v0.2 с
`interrupted`. Перед миграцией сохраняется `manifest.before-v02.json`, а аккаунт
проверяется свежим read-only запросом. Другой профиль не может дописать архив.
Исходные RAW/медиа не удаляются. Не запускайте старую v0.1 на архиве после миграции.

Завершённые запросы восстанавливаются из проверенных RAW (размер + SHA-256).
Индексы объединяются с восстановленными данными; уже пройденные стадии могут
показываться в UI во время локального восстановления, без повторных запросов API.
Сеть используется для проверки аккаунта, отсутствующих ответов и недостающих файлов.
Исправление фильтра chat_id также может обнаружить ранее пропущенные чаты: их
карточки/сообщения будут получены до продолжения медиа.

`manifest.stages` содержит статусы стадий, `current_stage` — текущую стадию,
`index/recovery.sqlite3` — атомарный журнал запросов, медиа и активных проблем.
Manifest/индексы заменяются атомарно; блокировка не допускает одновременного
resume одного архива. После аварийного закрытия оставшийся `running` доступен
для восстановления. Начальная проверка большого архива может занять время.

Медиа пишутся потоково блоками 256 КиБ в `.part`, затем переименовываются.
Проверенные сохранённые файлы пропускаются независимо от их позиции в списке.
Повреждённый/отсутствующий файл скачивается заново; неудачные загрузки учитываются
отдельно. Голосовые запрашиваются по одному ID: отсутствующие ответы записываются
в `index/voice/`, а ранее скачанные голосовые не требуют новых временных ссылок.

HTTP 429 учитывает `Retry-After` и `X-RateLimit-Retry-After`; временные сетевые
сбои и 5xx повторяются с ограничением. Постоянные 4xx не вызывают пять попыток.
Подтверждённый 422 «Объявление не принадлежит пользователю» сохраняется как
`unavailable_by_api` для конкретного объявления, не как ошибка всех архивных
статусов. Доступные данные списка/контекста остаются в RAW.

Счётчики показывают уникальные активные проблемы: **Ошибки** — неисправности
экспортёра и исчерпанные временные сбои; **Предупреждения** — ограничения,
недоступность API и безопасные пропуски. Исторический журнал v0.1 сохраняется
отдельно; его число событий не переносится в текущий счётчик ошибок. Разрешённая
при повторе ошибка перестаёт быть активной. `partial` возможен при ограничениях
даже с нулём ошибок. Подтверждённо недоступные ресурсы не опрашиваются при каждом
resume; для нового снимка с изменившимися правами/данными используйте новый экспорт.
